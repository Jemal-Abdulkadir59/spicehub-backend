🧩 automatically update updated_at
⚙️ 1. Create a Trigger Function (Reusable for All Tables)
This function will automatically update updated_at whenever a row is modified.

-- Function: auto_update_timestamp
CREATE OR REPLACE FUNCTION auto_update_timestamp()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = NOW();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

⚙️ 2. Attach Trigger to Tables That Have updated_at
Here’s the trigger setup for all tables that contain an updated_at column.
-- USERS
CREATE TRIGGER set_timestamp_users
BEFORE UPDATE ON public.users
FOR EACH ROW
EXECUTE FUNCTION auto_update_timestamp();

-- ORDERS
CREATE TRIGGER set_timestamp_orders
BEFORE UPDATE ON public.orders
FOR EACH ROW
EXECUTE FUNCTION auto_update_timestamp();

-- MENU ITEMS
CREATE TRIGGER set_timestamp_menu_items
BEFORE UPDATE ON public.menu_items
FOR EACH ROW
EXECUTE FUNCTION auto_update_timestamp();

-- MENU CATEGORIES (optional)
CREATE TRIGGER set_timestamp_menu_categories
BEFORE UPDATE ON public.menu_categories
FOR EACH ROW
EXECUTE FUNCTION auto_update_timestamp();

-- You can add more as needed, e.g. reviews, kitchen_orders, deliveries if you add updated_at columns later.

🧩 Auto-Set paid_at When Status Becomes “paid”
🧠 You want to automate this — because manually adding paid_at every time is not practical.
Let’s extend the trigger so it works for both "paid" and "completed" statuses 👇

If you want to automate that, you can create a trigger:

-- 1️⃣ Step 1 — Create/Replace the Trigger Function
CREATE OR REPLACE FUNCTION set_paid_at_on_payment_status()
RETURNS TRIGGER AS $$
BEGIN
  -- If status is 'paid' or 'completed' and paid_at is not already set
  IF (NEW.status IN ('paid', 'completed')) AND (NEW.paid_at IS NULL) THEN
    NEW.paid_at := NOW();
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 2️⃣ Step 2 — Attach the Trigger to the Payments Table
DROP TRIGGER IF EXISTS set_paid_at_trigger ON payments;

CREATE TRIGGER set_paid_at_trigger
BEFORE INSERT OR UPDATE ON payments
FOR EACH ROW
EXECUTE FUNCTION set_paid_at_on_payment_status();



✅ So now, whenever the status is updated to "paid", the paid_at column automatically fills 
in with the current timestamp.

🧩Auto-generate a transaction ID
✅ Fix Option 1: Auto-generate a transaction ID
if you prefer readable transaction codes (like TX-20251016120001), you can use a trigger:

CREATE OR REPLACE FUNCTION generate_transaction_id()
RETURNS TRIGGER AS $$
BEGIN
  IF NEW.transaction_id IS NULL THEN
    NEW.transaction_id := 'TX-' || TO_CHAR(NOW(), 'YYYYMMDDHH24MISS') || '-' || SUBSTRING(gen_random_uuid()::TEXT, 1, 8);
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER set_transaction_id
BEFORE INSERT ON payments
FOR EACH ROW
EXECUTE FUNCTION generate_transaction_id();

✅ Fix Option 2: Auto-fill started_at when status = 'preparing'

If you prefer automation like the payments trigger, use this trigger:

CREATE OR REPLACE FUNCTION set_started_at_on_preparing()
RETURNS TRIGGER AS $$
BEGIN
  IF (NEW.status = 'preparing') AND (NEW.started_at IS NULL) THEN
    NEW.started_at := NOW();
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS set_started_at_trigger ON kitchen_orders;

CREATE TRIGGER set_started_at_trigger

🔹 Trigger: Auto-set pickup and delivered times

CREATE OR REPLACE FUNCTION set_delivery_timestamps()
RETURNS TRIGGER AS $$
BEGIN
  -- When rider picks up the order
  IF NEW.status = 'picked_up' AND NEW.pickup_time IS NULL THEN
    NEW.pickup_time := NOW();
  END IF;

  -- When order is delivered
  IF NEW.status = 'delivered' AND NEW.delivered_time IS NULL THEN
    NEW.delivered_time := NOW();
  END IF;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS set_delivery_timestamps_trigger ON deliveries;

CREATE TRIGGER set_delivery_timestamps_trigger
BEFORE INSERT OR UPDATE ON deliveries
FOR EACH ROW
EXECUTE FUNCTION set_delivery_timestamps();

1️⃣ Using Hasura Event Triggers (Recommended)
vent triggers let Hasura listen for changes in your database (like a new order) and automatically run a webhook 
or function.

Step-by-step
Go to Hasura Console → Events → Event Triggers.
Click Create → Event Trigger.
Trigger Name: clear_cart_after_order
Schema / Table: orders
Operations: INSERT (when a new order is created)
Webhook URL:
This is your backend endpoint (e.g., http://localhost:3000/clear-cart) that will receive the event payload.
Save the trigger.

✅ What happens:
When a user places an order, Hasura fires the event.
Your webhook receives it and deletes all cart_items for that user automatically.
The trigger listens only for INSERT events on the orders table.
Every time a new order is created, Hasura sends a payload to your webhook (your backend).
The webhook receives the user_id of the order and can safely delete only that user’s cart items.

!🔹 If you want to use GraphQL instead of a webhook to clear the cart after checkout, you don’t need an 
Event Trigger at all — you can do it in one mutation using Hasura’s nested inserts and deletes.

-- Enable UUID generation
CREATE EXTENSION IF NOT EXISTS "pgcrypto";

-- =====================================
-- USERS
-- =====================================
CREATE TABLE public.users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  full_name TEXT NOT NULL,
  email TEXT UNIQUE NOT NULL,
  phone TEXT UNIQUE,
  password_hash TEXT NOT NULL,
  role TEXT CHECK (role IN ('customer', 'admin', 'kitchen', 'rider')) DEFAULT 'customer',
  avatar_url TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- =====================================
-- MENU CATEGORIES
-- =====================================
CREATE TABLE public.menu_categories (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  description TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- =====================================
-- MENU ITEMS
-- =====================================
CREATE TABLE public.menu_items (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  category_id UUID REFERENCES public.menu_categories(id) ON DELETE SET NULL,
  name TEXT NOT NULL,
  description TEXT,
  price NUMERIC(10,2) NOT NULL,
  image_url TEXT,
  is_available BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- =====================================
-- CART (user’s temporary cart before placing an order)
-- =====================================
CREATE TABLE public.cart_items (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES public.users(id) ON DELETE CASCADE,
  menu_item_id UUID REFERENCES public.menu_items(id) ON DELETE CASCADE,
  quantity INT NOT NULL CHECK (quantity > 0),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (user_id, menu_item_id)
);

-- =====================================
-- ORDERS
-- =====================================
CREATE TABLE public.orders (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES public.users(id) ON DELETE SET NULL,
  total_amount NUMERIC(10,2) NOT NULL DEFAULT 0,
  status TEXT CHECK (status IN ('pending', 'preparing', 'ready', 'delivering', 'completed', 'cancelled')) DEFAULT 'pending',
  payment_status TEXT CHECK (payment_status IN ('unpaid', 'paid', 'refunded')) DEFAULT 'unpaid',
  delivery_address TEXT NOT NULL,
  delivery_instructions TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- =====================================
-- ORDER ITEMS
-- =====================================
CREATE TABLE public.order_items (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  order_id UUID REFERENCES public.orders(id) ON DELETE CASCADE,
  menu_item_id UUID REFERENCES public.menu_items(id) ON DELETE SET NULL,
  quantity INT NOT NULL CHECK (quantity > 0),
  unit_price NUMERIC(10,2) NOT NULL,
  total_price NUMERIC(10,2) GENERATED ALWAYS AS (quantity * unit_price) STORED
);

-- =====================================
-- PAYMENTS
-- =====================================
CREATE TABLE public.payments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  order_id UUID UNIQUE REFERENCES public.orders(id) ON DELETE CASCADE,
  method TEXT CHECK (method IN ('cash', 'card', 'mobile_money')) NOT NULL,
  amount NUMERIC(10,2) NOT NULL,
  status TEXT CHECK (status IN ('pending', 'completed', 'failed', 'refunded')) DEFAULT 'pending',
  transaction_id TEXT,
  paid_at TIMESTAMPTZ DEFAULT NOW()
);

-- =====================================
-- KITCHEN ORDERS
-- =====================================
CREATE TABLE public.kitchen_orders (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  order_id UUID UNIQUE REFERENCES public.orders(id) ON DELETE CASCADE,
  chef_id UUID REFERENCES public.users(id) ON DELETE SET NULL,
  status TEXT CHECK (status IN ('pending', 'in_progress', 'completed')) DEFAULT 'pending',
  notes TEXT,
  started_at TIMESTAMPTZ,
  completed_at TIMESTAMPTZ
);

-- =====================================
-- DELIVERIES
-- =====================================
CREATE TABLE public.deliveries (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  order_id UUID UNIQUE REFERENCES public.orders(id) ON DELETE CASCADE,
  rider_id UUID REFERENCES public.users(id) ON DELETE SET NULL,
  status TEXT CHECK (status IN ('pending', 'assigned', 'picked_up', 'delivered', 'cancelled')) DEFAULT 'pending',
  pickup_time TIMESTAMPTZ,
  delivery_time TIMESTAMPTZ
);

Allow pickup_time to be empty initially
pickup_time should be nullable.
That’s the realistic approach — both times should be set later as the delivery progresses.

-- =====================================
-- REVIEWS
-- =====================================
CREATE TABLE public.reviews (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  order_id UUID REFERENCES public.orders(id) ON DELETE CASCADE,
  user_id UUID REFERENCES public.users(id) ON DELETE SET NULL,
  rating INT CHECK (rating BETWEEN 1 AND 5),
  comment TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

  DROP TRIGGER IF EXISTS set_delivery_timestamps_trigger ON deliveries;

  CREATE TRIGGER set_delivery_timestamps_trigger
  BEFORE INSERT OR UPDATE ON deliveries
  FOR EACH ROW
  EXECUTE FUNCTION set_delivery_timestamps();

✅## if you want fetche data public without auth(logged in)
Step 1: allow anonymous role in Hasura
In your Hasura environment config (e.g., docker-compose.yml or .env),
add these lines:
  HASURA_GRAPHQL_JWT_SECRET: '{"type": "HS256", "key": "your_nextauth_secret_here"}'
  HASURA_GRAPHQL_UNAUTHORIZED_ROLE: "anonymous"
This tells Hasura:
“If a user doesn’t send a JWT, treat them as anonymous.”

Step 2: add “anonymous” role permissions in Hasura Console
Go to Hasura Console → Data → menu_items → Permissions:
Add Role: anonymous
Check ✅ select permission
Row filter: {} (no filter — allow all)
Columns: choose what public should see
Then click “Save Permissions”.
Now anyone (even without login) can fetch menu items.
